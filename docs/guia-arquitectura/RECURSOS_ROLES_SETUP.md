# Recursos de roles y contadores

Entrega local de roster, membercount, serverstats y reactionrole: 49/63 comandos remodelados. Menús paginados para 100 listas/25 contadores, formularios con borrador y guardado CAS, permisos frescos y controles de sesión. Se conservan stores, aliases, slots y metadatos desconocidos de las entradas existentes.

Guardar cambia preferencias; Publicar aplica el cambio a Discord. Retirar elimina únicamente el mensaje del bot vinculado, conservando la configuración. El contador usa un canal existente; desvincularlo no borra canales. Las actualizaciones programadas nunca crean reemplazos de mensajes borrados. Hidratación de miembros una vez por servidor y omisión de nombres ya actualizados; listas con un recorrido de miembros y límites de embeds. Las presencias dependen del intent/datos disponibles.

Las publicaciones se serializan por recurso. Antes de crear se persiste un nonce; el ID confirmado se guarda antes de añadir reacciones. Un fallo de resultado desconocido impide repetir la creación y solo permite conciliar un mensaje con marcador del mismo recurso, autor del bot y coincidencia única entre los últimos 50 mensajes. Si no se puede identificar con certeza se requiere revisar/introducir el ID; no se promete recuperación ilimitada. Una configuración cambiada antes de publicar bloquea el efecto. El cierre deja de admitir operaciones y espera las aceptadas antes del flush existente.

Roles por reacciones conserva MESSAGE_ID/remove_others/Parameters. Nuevas ediciones usan CONFIG_ID estable y requieren canal; los paneles antiguos siguen atendiendo por su ID. Se valida jerarquía, roles administrados y Administrator. Se corrigió el consumidor antiguo: referencia de mensaje inexistente y comprobación invertida al retirar el rol anterior. Una reacción no configurada no retira roles. La elección única asigna el nuevo rol antes de quitar los anteriores; elecciones rápidas y retirada durante la consulta no conceden una selección obsoleta. Las operaciones de un miembro se ordenan y se drenan al cerrar. No se afirma atomicidad de varias llamadas REST: un fallo intermedio conserva los efectos ya confirmados.

Verificación temporal registrada durante la implementación: publicación 7 grupos, formularios/listas/contadores 7, paneles de reacción 7, jobs 8. Tras la revisión final se ejecutaron otros 7 grupos del protocolo de publicación (incluida separación entre paneles con igual título) y 11 del consumidor real de eventos: parcial, permisos, modo único/múltiple, mismo rol con otro emoji, configuración retirada, elecciones rápidas y cierre. SDK real con transporte aislado; fixtures de persistencia con bases Mongo propias, eliminadas. No se crearon recursos ni se enviaron mensajes a Discord real. Se mantienen únicamente los 3 archivos/25 tests originales; no se agregan scripts o tests permanentes.
