# Feeds · configuración por servidor

Entrega local de youtube/tiktok/twitch/twitter, acumulado 45/63. Se conservan aliases, campos de suscripciones/cuentas y workers existentes. Sin despliegue, credenciales reales ni publicaciones externas durante la verificación.

YouTube/TikTok: canal y lista de creadores en formulario, mensajes por creador en editor de entradas. Las plantillas nuevas se guardan en `<plataforma>.templates` del servidor y el consumidor prefiere esa plantilla, con fallback de lectura a la plantilla global antigua. El editor no escribe el mensaje compartido de youtube_log/tiktok; así otro servidor no cambia de texto. Las suscripciones antiguas conservan su identidad/clave de historial, aunque se normalizan las entradas nuevas y se deduplican por creador. YouTube acepta ID UC o URL /channel/UC de sus dominios admitidos. No se añade resolución de handles ni nuevas APIs.

TikTok sigue desactivado por la incompatibilidad ya declarada en el publicador. Sus menús de preferencias y plantillas lo indican. No se reactiva el scraper ni se afirma que publicar funciona. Twitch conserva el objeto de streamer/usuario/mensaje/stream_id, el ID del servidor y roles ping/give. El rol de asignación requiere jerarquía y permisos; los destinatarios son miembros del servidor. Los campos/arrays ausentes necesarios se completan solo al guardar y sin reemplazar los existentes.

Twitter conserva cuenta/ID/canal/mensaje/retweets. Al cambiar usuario se busca coincidencia exacta mediante el cliente Twit existente; se puede introducir usuario e ID manualmente sin consulta. La consulta tiene timeout de 8 s y SSL estricto según la [API del cliente Twit](https://github.com/ttezel/twit#var-t--new-twitconfig). No se da por disponible la API del proveedor ni se migra autenticación/v1.1. Una preparación remota ocurre tras ACK y antes del guardado; expiración, shutdown o permisos revocados impiden el commit posterior. Validación fallida conserva borrador.

Se corrige la validación antigua de longitud exactamente 18 en consumidores Twitch/Twitter: admite IDs de Discord de 17–20 dígitos mediante helper compartido. No se altera su programación ni cachés/historial globales. La arquitectura de historial y la selección de múltiples guilds del antiguo worker de Twitter quedan fuera de esta entrega de setups; no se presenta como una reescritura de todos los publicadores.

Diez grupos temporales: builders/idiomas, normalización sin cambiar identidad antigua, suscripciones, plantillas aisladas/fallback, Twitch/defaults, lookup exacto/fallo, cuenta manual, expiración/revocación durante lookup, job real de YouTube con transporte/datos/cron aislados para dos guilds y validación de IDs. Mongo/SDK reales para formularios, sin credenciales ni requests externos. El fixture del job carga colors como el arranque para sus logs legacy. Bases propias eliminadas y cero rechazos no manejados; 25 originales/imports/diff comprobados. No se agregan tests/scripts permanentes ni se afirma disponibilidad de APIs externas o recorrido Gateway.
