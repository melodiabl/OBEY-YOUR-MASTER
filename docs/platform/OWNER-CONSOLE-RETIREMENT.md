# Consola del dueño · retirada de ejecución de código por Discord

`eval`/`evaluate` y `detailedeval`/`detailedevaluate`/`detailevaluate`/`detaileval` conservan nombre, alias, categoría Owner, tipo bot, uso y ausencia de cooldown explícito. Se retira la ejecución de JavaScript por mensaje, incluido el permiso basado en un ID fijo del creador anterior. La descripción y respuesta explican que la consola está retirada; no hay fecha de eliminación de los nombres.

Motivo y alcance: el contrato común del proyecto exige «Sin JS del usuario, eval ni plantillas ejecutables». Ambas entradas anteriores ejecutaban texto del usuario dentro del proceso con acceso al cliente y sus servicios. El filtro por una palabra de detailedeval no era una frontera de aislamiento. La demostración usa exclusivamente VM, cliente, módulos y transporte ficticios, con un marcador sintético inofensivo; no es evidencia de abuso pasado. No se inspeccionan secretos reales.

Los adaptadores no leen, convierten, concatenan, evalúan, importan ni pasan a otro servicio los argumentos recibidos. El aviso no incluye código recibido, resultados, rutas, errores internos, secretos ni datos del cliente. No se usa vm/Function/eval/shell ni un endpoint alternativo para ejecutar texto. El adaptador y servicio tampoco reinician, publican slash ni escriben datos, registros o módulos. La instrumentación y cooldown generales del dispatcher conservan su comportamiento.

La lectura del aviso utiliza IDs exactos del archivo actual de propietarios y miembro/canal/bot frescos, sin añadir Administrator. El ID histórico no concede acceso por sí solo. Se admiten los idiomas cargados es/en/de/in, con sufijos regionales válidos; de/in conservan el fallback español del catálogo nuevo. Una lectura de idioma fallida o inválida usa una respuesta genérica en español; errores de acceso/archivo/plazo/entrega quedan contenidos. Se conserva el plazo de diez segundos del guard compartido; no hay respuesta autorizada tardía. El resultado se responde solo al mensaje, con allowedMentions vacío, sin abrir DM ni elegir otro canal.

Migración: usar los comandos concretos del bot para cada operación. `botfilename` ofrece identidad y versiones al dueño; el código se modifica y despliega mediante el flujo de mantenimiento del proyecto. No se sustituye la consola por otra ruta de JavaScript arbitrario. El despliegue de imágenes ya existe y está verificado; el recorrido de aviso en Discord real sigue pendiente.

Pruebas: demostrar en VM el grant histórico ajeno a ownerIDS y ejecución del marcador sintético, probar las entradas nuevas con argumentos que fallan si se leen/coercionan y datos privados protegidos, permisos retirados, fallos de idioma/archivo/espera/entrega, idiomas y metadatos. Sin comandos ni mensajes reales en Discord. Conservar los tres archivos/25 pruebas originales y retirar verificadores temporales tras conservar TAP/JSON.

La retirada se limita a estas dos consolas públicas. Otras interpolaciones eval de código heredado, otras operaciones Owner/Settings, recibos, auditoría, coordinación entre procesos, G01/G02 y aceptación real permanecen en el plan; no se declara libre de eval todo el repositorio.
