# P0 · familia ban · 25/10/2026

`ban`, `idban`, `useridban` y el ban slash usan `performBan` como única ejecución del efecto Discord. Los tres adaptadores prefix delegan en el orquestador existente de moderación, retirando sus grandes bloques inline. Se espera la respuesta de Discord antes de anunciar éxito, contar, notificar o registrar. [Evidencia](evidence/p0-ban-20261025.json).

El servicio valida IDs, política y días; rechaza actor, bot y propietario como objetivo. Refresca roles de la guild, actor, bot y objetivo. La jerarquía usa `Role.comparePositionTo`, con rechazo si el orden no se puede determinar; los comandos por ID dejan de saltarse ese control sobre miembros presentes. Se comprueban BanMembers del bot y `bannable` del objetivo fresco. Un fallo de lectura no se interpreta como ausencia: solo `10007` permite la vía de no miembro en los comandos de ID y slash. `ban` prefix continúa exigiendo miembro.

Se conservan las concesiones existentes de prefix: Administrator, propietario de guild/configurado, adminroles y roles/usuarios por comando. `idban` sigue leyendo `cmdadminroles.ban`; `useridban` conserva su clave propia. BanMembers nativo sin esas concesiones no concede acceso a prefix, mientras slash conserva BanMembers y su excepción de jerarquía para el dueño. Prefix aplica la comparación estricta de actor incluso al dueño. Esto estrecha las rutas de ID que antes no comparaban jerarquía, sin ampliar permisos.

El SDK actual no reconoce el campo `days` que enviaba el ban prefix. Se sustituye por `deleteMessageSeconds`, de 0 a 604800. Prefix exige un entero de 0 a 7 si se indica el token numérico; el cero deja de contaminar el motivo. Slash conserva su clamp existente. La ayuda aclara que los días indican mensajes que se borran y que el ban es permanente. El alias legacy `tempban` se conserva: no se ha añadido un scheduler de desbaneo ni una función temporal nueva.

Se mantienen los efectos diferenciados: `ban` prefix cuenta y avisa por DM, `ban`/`useridban` usan el adminlog opcional, `idban` no añade esos efectos y slash sigue creando el caso en `ModerationSchema`. Todos se ejecutan después de confirmar Discord. Contador, DM y log tienen esperas acotadas y avisos separados; un destino de log ausente no borra su configuración. Las respuestas nativas es/en deshabilitan menciones, acotan el motivo y reparan Unicode truncado; prefix conserva el footer. Se retiran la interpolación del comando crudo y el GIF inline antiguo.

En `runModeration`, la asignación/creación del caso queda acotada a cinco segundos para ban, kick y timeout. Un timeout o error de historial mantiene la sanción confirmada, sin repetirla, y advierte del registro. La operación de almacenamiento puede acabar después; no existe aún recibo duradero ni coordinación estricta de ban/unban. Este cambio compartido tiene pruebas de regresión para kick/timeout, pero no acepta sus adaptadores prefix ni completa su migración.
